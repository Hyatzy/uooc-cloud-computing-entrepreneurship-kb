1   云平台日常运行管理
1.1  资源管理
在云平台中其中的核心内容就是数据资源，其不仅仅是支撑整
体平台的基础，同时也是为客户提供服务的最终目标。按照数据形
式可以划分为虚拟和物理资源，按照资源数量可以划分为单个资源
和群资源。对单个、群资源进行管理是运行管理中的重点内容，主
要内容后资源的识别、例如、维护、分配、优化等各项内容。通过
对资源群进行优化，才能够更加清晰的看到群落中的内容。
1.2  自动化维护
由于云中的数据信息量巨大，这就需要具备更加高效的运行管
理机制，这就需要利用自动化技术。构建自动化维护体系，可以完
成大部分的运维工作，包括信息数据的自动化备份、自动恢复等，
从而解放人为工作，降低人力成本。
1.3  运维人员技术能力
想要确保云平台正常运行，必须要注重人才的培养，综合素质
高的人才永远是市场所需。运维人员需要掌握计算机软硬件、操作
系统的技术，同时也要具备多个脚本语言能力。如果自动化运维手
段无法实现相应的功能时，则复合型人才是最好的补充手段。
2   云平台的维护管理方案
云平台维护管理出了日常管理之外，还包括安全性管理，其主
要表现在 ：
2.1  监控技术
由于云资源体系十分庞大，需要运维人员时刻都掌握每项资源
的运行状态，仅凭借人工操作无法全面保障云平台的运行安全性，
需要借助相应的监控技术才可以达到以上目的。其主要的监控内容
有 ：（1）物理资源监控。云平台需要大量的硬件设备提供支持，通
过监控技术可以掌握物力资源的运行情况，在硬件出现故障时可以
展开精准判定，从而加强对物理资源的维护工作 ； （2）性能指标监
控。通过利用迁移技术， 例如监控系统检测到某个硬件性能不足时，
为了避免影响其正常业务开展，可以将虚拟资源迁移到性能更好的
硬件上，从而保证业务正常开展 ； （3）资源容量监控。在虚拟机创
建时无法一次性完全分配各项资源，而是随着虚拟机在运行中逐渐
进行资源优化，这就要对各类资源容量进行监控。
2.2  安全控制技术
采用规范化管理模式，加强安全管理保障，服务商需要采用更
加有效的服务功能保障信息安全，从而提高用户对云平台的信任度
和依赖性。加强云平台运行环境质量，需要从访问控制、身份鉴别、
信息标记、强制访问控制、系统安全审计、用户信息保障、程序执
行保护方面出发。这样才能够全面保障云平台的运行安全。
3   云平台资源优化方案
云平台资源优化是保障平台运行效率、安全、质量的重要一环，
可以说云平台的发展就是优化资源。
3.1  服务器资源优化
将所有的物理资源按照 1 ：16的比例划分出虚拟机，这样即可
增加虚拟机的数量，提高运行能力。这样可以同时支持多个系统以
及多个应用。在实际优化当中，由于个别虚拟机的占用率峰值会达
到 15% 以上、整体内存峰值达到 90% 以上，所以可以对内存进行
适当扩充，将系统 CPU 核数按照 1：8的比例进行配置，例如当今
普遍采用8核 CPU，因此可以配置内存为 64G。
物理资源是支撑云平台运行的基础，例如有14个物理资源，总
系统分为4个子系统 A、B、C、D，其 中A、B 系统是主运行系统，C、
D 是备用系统，可以将 A 交互系统分配 5个物理资源、B 服务器系
统分配 8个物理资源，其余的都用作于 C、D 系统。这样可以在保
障 A 和 B 系统正常运行的基础上，采用 C 和 D 备用系统减低运行
风险，不需要创建新的子系统即可实现保护功能。此外，如果需要
扩展功能，在 A 和 B 系统资源占满的基础上，可以向 C 和 D 的系
统中扩展。 如果应用层使用了HA软件， 则不建议将虚拟机进行整合，
但是可以在开发新虚拟机时提供使用。
3.2  存储资源优化
（1）如果虚拟机对 IO 的要求较高，可以将存储数据传输到
RAID1+0上，其余虚拟机放入到 RAID5上。例如 PLTP类型应用系
统，即可保存在 RAID1+0当中。
（2）如果应用系统对 IO 的要求较高，可以把数据信息放入到
存储多系统中。该存储多系统主要是适用于吞吐量在 300Mb/s 以上
或 IOPS大于 1200的数据。
（3）可以在 RAID1+0当中存储 A 业务平台数据以及业务处理
数据。
（4）在 RAID1+0中放入虚拟机服务器，采用云存储技术将数
据信息备份，这样即可在 RAID1+0出现故障时恢复信息数据。
3.3  应用平台迁移与云平台资源整合
在云平台资源优化当中，想要确定虚拟机资源规划比例、服务
上运行多少虚拟机，无法通过指定比例进行计算，而是通过资源调
查、分析，根据云资源群、系统情况，按照下述原则进行分配 ：
（1）如果某些系统资源利用率在 50% 以下，则优先向此系统进
行迁移。将系统资源利用率在 50% 以及利用率在 30% 以下的服务
器要进行虚拟机整合，共享一台服务器。
（2）多个服务器资源利用率在 30% 以下时，需要进行虚拟器整
合，共用一个服务器。
（3）如果不同系统的峰值不重合，例如部分系统使用峰值在白
天、另一部分在夜晚时，则可以考虑进行虚拟器整合，并按照峰值
时间点进行调整，避免出现峰值重叠情况。
（4）如果不同系统的资源需求不同，例如某个系统对内容要求
高、对 CPU 处理性能要求低，而另一个系统对内存要求高、 CPU
性能要求低，则可以考虑虚拟机整合。
（5）如果物理资源利用率低于 60%，则可以增加虚拟机数量，
如果物理资源利用率在80% 以上，则不可增加虚拟机。
（6）物理资源利用率超过 90% 时，可以将内部虚拟机转移到负
荷较低的物理资源中。
4   结束语
综上所述，云平台在当今社会生产与服务当中有着重要地位，
想要全面发挥云平台的积极作用，就必须要做好云平台的运行与维
护管理工作，确保云平台日常运营符合用户需求。同时也要不断对
云平台资源进行优化调整，实现性能最优、利用率最优，（转下页）

我国通信网络建设推动了各项通信基础设施的完善和发展，为
提升通信工程的建设质量，对现用通信交换工程进行必要的改造，
进而提升组网系统运行安全。由于对通信交换和组网工程进行改造
对通信网络建设领域的其他一些基础功能发展有关键性影响。要根

1   我国通信交换工程进行改造和组网的作用
通信交换工程是我国通信系统运行的基础，随着通信技术的持
续发展，一些新设备和新保障方式不断涌现，因此，一些必要的工
程改造成为了必然要完成的工作。通信交换网络是我国电力进行生
产、调配和营销的基础，因为总体发展的时间相对较短，表现在通
信交换网络的实际应用过程中的一些现实问题。为从根本上有效保
障这些通信功能的作用发挥，就要对工程的组网实施有效改造，经
改造试用通过后才可以更好适应当前社会发展需求，将的业务范围
进一步扩展，通信能力得到更大支持。不但如此，通信网络运行的
可靠性和网络传输速度等重要性能参数的提升，都要求通信网络需
要采取更为合理的软硬件改造，以满足当今社会发展对于通信保障
的根本需求。
2   通信交换工程的组网及改造措施研究
2.1  通信传输工程的改造组网
对于通信交换工程的改造及其组网建设来说，要从中继服务的
传输途径进行改造，以中继系统进行传输的交换设备中，需要对整
个体系进行综合的设计，包括服务器以及各个中间应用环节和传输
处理单元等，确保需求连接的充分实现。通过这样的安排，既提升
了整个通信交换网络中各种业务进行的速度，又可以形成更多有价
值的拓展业务内容，从而提升设备使用的灵活性。
整个改造工程要基于前期建设的设备资源，将这些资源充分利
用，可以降低投入成本，减少人力和物力的消耗。要从信道传输方
式开始，对整个通信交换工程完成相应的改造以及组网，传统通信
模式中因为设备过于陈旧难以提供高效率高质量的通信功能，很多
通信传输过程需要进行深度改造才能满足当前使用需要。既要考虑
当前的使用，又要兼顾未来发展需要，同时还有改造性价比的提升
问题。
在对通信交换工程进行改造的过程中，要严格按照正确的设计
顺序对各通信链路中的数据参数进行配置。一般情况下对主要参数
的配置都是从高向低的层次进行，因为整个系统在正常运行中还会
存在互相影响的情况，一些参数内容会有变化。为此，需要增加一
些 MTP 信令点，并根据实际信令点情况适量增加相关链路集，以
及线路路由设备。中继信道进行的数据参数配置， 要按照层次方向、
子路由、中继群、中继电路的次序依次完成增加任务。
2.2  优化完善数字同步通信机制
通信交换网络的现代化发展，是以满足实际生产生活需要为根
本目标，基于实际需要的同步通信机制是整个通信交换工程建设和
组网改造的根本目的。以实际需求来看，语音通话只是通信系统中
最简单的部分，包括电视电话会议、局域网数据共享、虚拟工作网
络、大数据、云计算等，这些业务或服务将深刻影响人们的日常生
活。而基于这些特色和个性化的需求，在同步机制基础上建立完善
数字化和智能化的通信体系，并优化各种配套功能建设。将各种功
能进行有效整合，并体现到实际的工程改造中，推动改造取得预期
建设目标。
2.3  设计统一管理的通信交换网络综合管理平台
通信交换网内包含有多种信道形式的通信方式设计，其目的就
是要保证网络的全面兼容性，而这种设计对于系统的维护管理带来
了一定的难度，而设计统一进行管理的综合管理平台是非常有效的
解决办法。管理平台可以通过独立的管理服务器进行登录管理，对
各个应用环节进行监督检查，一些应急中断问题进行实时显示。包
括一些远程处理功能，提升系统使用的总体稳定性。
2.4  对应用软件进行调试
在通信交换工程的硬件基础工作基本完成各种改造和组网任务
后，要对系统的运行情况通过软件进行测试，且这些应用软件本身
也需要进行调试和参数的配置。在调试的过程中，必须确保物理联
通已经实现，否则这种调试工作将无法开展。在调试过程中，不但
要确保软件处于沟通状态，还要测试畅通情况，测试线路的丢包率，
以及应用软件的各项实际功能。包括计算机控制中心和各个节点站
的软件应用情况，都要可以正常运行，并发挥设计功能。测试可以
分步进行，尤其是一些较复杂的系统改造，需要分块分片进行调试，
可以提高调试效率，有利于发现并消除各种隐患问题。
3   结束语
综上所述，通信网络建设过程中，有时会涉及到对一些老旧的
通信交换设备进行升级改造，通过这些改造，以及对组网安全有显
著帮助的功能进行完善。总的来说，交换工程组网的总体改造工作
非常重要，而网络通信时代的持续发展对于通信交换工程的建设提
出非常高的标准和要求，为有效保障这些通信技术的性能发挥，就
必须强化对交换工程实施全面彻底的改造。针对性做好各方面的细
节工作，完善通信系统建设的各方面工作，从根本上推动改造完成。
